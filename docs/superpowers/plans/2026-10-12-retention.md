# Retention (Step 6b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a periodic, batched, dry-run-by-default data-retention job to wallet and payment that deletes aged outbox/inbox/idempotency/reconciliation/webhook rows without ever touching ledger or other financial tables, with metrics and a Kibana rule/panel.

**Architecture:** `@billing/runtime` gains `drainBatches`. Each service has a `RunRetention` use case (application, no SQL) over a `RetentionRepository` port whose Kysely implementation runs one `delete top (N) … with (readpast, rowlock)` per call (or a capped count in dry-run). A separate `Worker` runs the use case every `RETENTION_INTERVAL_MINUTES`. Metrics (`billing.retention.rows`, `billing.retention.last_success_timestamp_seconds`) feed a new Kibana rule `billing-retention-stalled` and one dashboard panel, generated by the existing `tools/kibana` generators. Spec: `docs/superpowers/specs/2026-10-12-retention-design.md`.

**Tech Stack:** TypeScript (ESM, NodeNext), Kysely + SQL Server, OpenTelemetry (via the existing `Telemetry` wrapper), Vitest (unit `*.test.ts`, integration `*.integration.test.ts` with testcontainers), pnpm via `corepack pnpm`, existing Kibana generators in `tools/kibana`.

## Plan-level decisions (applied to the spec in Task 11)

1. Payment's next migration is `003-retention-indexes` (payment already has `001-init`, `002-metadata`); wallet's is `006-retention-indexes` (tenant schema).
2. Policy names double as the metric `table` label: wallet `outbox_sent`, `processed_messages`, `idempotency_keys`, `reconciliation_items`, `reconciliation_runs`; payment `webhook_attempts`, `webhook_events`, `idempotency_keys`.
3. Policy execution order matters for foreign keys: wallet `reconciliation_items` → `reconciliation_runs` → `outbox_sent` → `processed_messages` → `idempotency_keys`; payment `webhook_attempts` → `webhook_events` → `idempotency_keys`. `webhook_events` deletion additionally requires that no attempt rows remain for the event.
4. Dry-run counts at most 1,000,000 rows per policy and runs once (no loop). For `reconciliation_runs` the dry-run count cannot anticipate items that the real run would delete first (it undercounts); documented.
5. The "last success" gauge is reported only when a run finished with zero errors (hitting the time budget is normal and still counts as success); it is the epoch seconds of that run, not an age.
6. `billing-retention-stalled` follows the `billing-service-silent` pattern: extras `maxAgeHours` (default 3) and `lookbackHours` (default 24); the rule's effective window is `lookbackHours * 60` and its `windowMinutes` key is required but unused; cross-check `maxAgeHours < lookbackHours`.

```ts
export interface DrainOptions {
  batchSize: number;
  /** Kiểm tra TRƯỚC mỗi lô; `false` thì dừng (hết ngân sách thời gian hoặc đang tắt). */
  shouldContinue?: () => boolean;
}

/**
 * Gọi `step(batchSize)` lặp lại để dọn dữ liệu theo lô: dừng khi một lô trả về ít hơn `batchSize`
 * (không còn gì đủ điều kiện) hoặc khi `shouldContinue()` trả `false`. Trả tổng số dòng.
 */
export async function drainBatches(
  step: (batchSize: number) => Promise<number>,
  options: DrainOptions,
): Promise<number> {
  let total = 0;
  for (;;) {
    if (options.shouldContinue && !options.shouldContinue()) return total;
    const rows = await step(options.batchSize);
    total += rows;
    if (rows < options.batchSize) return total;
  }
}
```

  'reconciliation_items',
  'reconciliation_runs',
  'outbox_sent',
  'processed_messages',
  'idempotency_keys',

export type WalletRetentionPolicy = (typeof WALLET_RETENTION_POLICIES)[number];

/** Trần khi đếm ở chế độ chạy thử (tránh đếm bảng khổng lồ). */
export const DRY_RUN_COUNT_CAP = 1_000_000;

export interface RetentionRepository {
  /**
   * Một lô: xóa tối đa `batchSize` dòng đủ điều kiện và trả số dòng đã xóa; khi `dryRun` chỉ đếm
   * (có trần `DRY_RUN_COUNT_CAP`) và không xóa gì.
   */
  purge(
    policy: WalletRetentionPolicy,

```ts
import { dateTime } from '@billing/database';
import { sql, type Kysely, type RawBuilder } from 'kysely';
import {
  DRY_RUN_COUNT_CAP,
  type RetentionRepository,
  type WalletRetentionPolicy,
} from '../../application/retention.js';
import type { WalletDatabase } from './schema.js';

/** Mọi bảng mà từng chính sách đọc hoặc ghi; test bảo vệ khẳng định không có bảng tài chính nào ở đây. */
export const RETENTION_TARGET_TABLES: Record<WalletRetentionPolicy, readonly string[]> = {
  reconciliation_items: ['reconciliation_items'],
  reconciliation_runs: ['reconciliation_runs', 'reconciliation_items'],
  outbox_sent: ['outbox'],
  processed_messages: ['processed_messages'],
  idempotency_keys: ['idempotency_keys'],
};

export class KyselyRetentionRepository implements RetentionRepository {
  constructor(
    private readonly db: Kysely<WalletDatabase>,
    private readonly schema: string,
  ) {}

  async purge(
    policy: WalletRetentionPolicy,
    cutoff: Date,
    batchSize: number,
    dryRun: boolean,
  ): Promise<number> {
    const t = (name: string) => sql.id(this.schema, name);
    const at = dateTime(cutoff);
    // `from` + `where` của từng chính sách; dùng chung cho đếm và xóa để hai chế độ không lệch nhau.
    const spec = ((): { target: RawBuilder<unknown>; alias: string; where: RawBuilder<unknown> } => {
      switch (policy) {
        case 'reconciliation_items':
          return {
            target: sql`${t('reconciliation_items')} as x`,
            alias: 'x',
            where: sql`x.case_status in ('RESOLVED', 'IGNORED') and x.created_at < ${at}`,
          };
        case 'reconciliation_runs':
          return {
            target: sql`${t('reconciliation_runs')} as x`,
            alias: 'x',
            where: sql`x.status <> 'RUNNING' and x.finished_at < ${at}
              and not exists (select 1 from ${t('reconciliation_items')} i where i.run_id = x.id)`,
          };
        case 'outbox_sent':
          return {
            target: sql`${t('outbox')} as x`,
            alias: 'x',
            where: sql`x.status = 'SENT' and x.sent_at < ${at}`,
          };
        case 'processed_messages':
          return {
            target: sql`${t('processed_messages')} as x`,
            alias: 'x',
            where: sql`x.processed_at < ${at}`,
          };
        case 'idempotency_keys':
          return {
            target: sql`${t('idempotency_keys')} as x`,
            alias: 'x',
            where: sql`x.created_at < ${at}`,
          };
      }
    })();

    if (dryRun) {
      const result = await sql<{ total: number }>`
        select count(*) as total from (
          select top (${sql.lit(DRY_RUN_COUNT_CAP)}) 1 as one
          from ${spec.target} where ${spec.where}
        ) counted`.execute(this.db);
      return Number(result.rows[0]?.total ?? 0);
    }
    const result = await sql`
      delete top (${sql.lit(batchSize)}) x
      from ${spec.target} with (readpast, rowlock)
      where ${spec.where}`.execute(this.db);
    return Number(result.numAffectedRows ?? 0);
  }
}
```

Notes for the implementer: (a) `delete top (n) x from <table> as x with (readpast, rowlock) where …` is the SQL Server form — if SQL Server rejects the hint placement with the alias, write the hint after the alias (`from schema.table as x with (readpast, rowlock)`) or drop the alias for single-table policies, keeping the same semantics; report the final form. (b) If `numAffectedRows` is not populated for raw `sql` in this Kysely/mssql dialect, obtain the count with `output deleted.<pk> into @t` / a trailing `select @@rowcount as n`, whichever works, and say which. (c) `dateTime(cutoff)` is the existing helper for date parameters in raw SQL. (d) `batchSize` and the cap are validated integers; `sql.lit` is acceptable for them.

export class RunRetention {
  constructor(private readonly deps: { /* as in Interfaces */ }) {}

  async execute(signal?: AbortSignal): Promise<RetentionReport> {
    const { uow, registry, clock, metrics, log, settings } = this.deps;
    const started = clock.now();
    const deadline = started.getTime() + settings.maxSecondsPerRun * 1000;

    const rows: RetentionRow[] = [];

              retention.purge(policy, cutoff, settings.batchSize, true),
            );

                );
                count += n;
                return n;
              },

            );
          }
        } catch (error) {
          errors += 1;
          log.warn({ err: error, tenantId: tenant.value, policy }, 'retention policy failed; continuing');
        }
        if (count > 0) rows.push({ tenant: tenant.value, table: policy, count });
      }
    }
